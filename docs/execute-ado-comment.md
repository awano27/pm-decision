# 承認した ADO コメントを実行する

既定では、承認（`OK N`）は「計画を記録する」だけです。ADO へのコメントだけ、承認のあとに kimeru が書けます。

## 有効にする

```powershell
python -m kimeru config set ado_org "<組織>"
python -m kimeru config set ado_project "<プロジェクト>"
python -m kimeru config set execute ado.comment
```

- `execute` に書けるのは、実装済みの `ado.comment` だけです。ほかの種類（`ado.update` など）を書くと、「未対応」と表示され、これまでどおり記録のみです。
- 認証は、あなた自身の `az` のサインイン（`az login`）です。トークンは記録も表示もしません。
- 元に戻す: `python -m kimeru config unset execute`

## 動き

1. コメントを書く判断は、**自動で決まったものも、承認待ちに回ります**（有効にした種類は、承認なしでは動きません）。
2. 承認の投稿に、**書かれる文面のすべて** と、「OK N で、作業項目 X に、上の文面のとおりコメントを書きます」が出ます。
3. `OK N` の返信で、その文面が **一字一句そのまま** 書かれます（末尾に、「kimeru が下書きし、本人が承認した文面です」の 1 行が付きます。`config set execute_signature 0` で外せます）。付帯の項目（下書きの印など）は送りません。
4. 結果が自分とのチャットに返ります: 「[kimeru 実行 #N] 実行しました。作業項目 7002 にコメント」／「実行できませんでした。理由」。すべての実行は `executions.jsonl` に残ります（日時、承認の番号、キー、種類、対象、結果）。

## 2 回書かない

- 実行の前に「実行中」を保存し、実行のあとに結果を保存します。
- 途中で止まったとき（「実行中」のまま）は、**自動では書き直しません**。「結果が分かりません」と 1 回知らせます。ADO を見て、書かれていなければ `再実行 N` と返信してください。
- 失敗しても、承認は残ります。直したら `再実行 N` と返信すると、失敗したものだけ、もう一度実行します。
- 1 つの失敗が、同じサイクルの他の承認の保存を妨げません。

## 相手への返信

`teams.reply` / `teams.post` は、送りません。承認すると、**送る文面だけ** の投稿（`[kimeru 送信用 #N]`）が自分とのチャットに返ります。iPhone で長押しして、コピーして送ってください。
`config set open_chat_link 1` にすると、相手とのチャットを開くリンクが付きます（実験的。リンクに文面は入りません）。

## 試験（会社 PC）

試験用の作業項目（誰の邪魔にもならないもの）を用意して、次を実行します。

```powershell
.\run-company-check.cmd T22
```

作業項目の番号を入力すると、承認の流れを 1 回通し、コメントが **1 回だけ** 書かれたかを確かめます。
