# 承認した優先度の変更を実行する（ado.update）

既定では、承認（`OK N`）は「計画を記録する」だけです。設定で有効にすると、作業項目の **優先度（`Microsoft.VSTS.Common.Priority`）だけ** を、承認のあとに kimeru が変更します（`daily` と `approvals` の経路だけ）。タグなど、ほかの項目は書きません。

## 有効にする

```powershell
python -m kimeru config set ado_org "<組織>"
python -m kimeru config set ado_project "<プロジェクト>"
python -m kimeru config set execute ado.update
```

- コメントも書くなら `config set execute ado.comment,ado.update`。元に戻す: `python -m kimeru config unset execute`
- 認証は、あなた自身の `az login` です。トークンは記録も表示もしません
- 実行しない経路（`demo`、`eval\`、`run`、`watch`）と、取り込み元の確認は [ADO コメント](execute-ado-comment.md) と同じです

## 承認するもの

承認の投稿に、次の行が出ます。

```text
→ OK 1 で、作業項目 7002（取り込み元の組織 contoso / プロジェクト Web）の優先度を 3 → 1 に変更します（判断したときの改訂 7）。
  ADO でこの改訂から変わっていれば変更せず、今の内容で確認し直しをお願いします
```

- `OK N` が承認するのは、この **作業項目・変更前と変更後の値・改訂番号（rev）・書き先** の組です。投稿のときに確定して保存し、その要約（ハッシュ）も残します。投稿のあとで記録が書き換えられていたら、書きません
- 改訂番号は、`pull ado` が作業項目を取り込んだときの値です。記録がないもの（サービスフックで届いたもの、この版より前に取り込んだもの）は、投稿の時点で「書きません」と出て、`OK N` は記録だけになります
- 優先度の値が 1〜4 の整数でないもの、優先度を含まない変更（タグだけなど）も、記録だけです
- 優先度とタグを一緒に変える判断では、優先度だけを書き、「ほかの項目（System.Tags）は書きません」と表示します

## 動き

1. `OK N` のあと、まず ADO から作業項目の今の改訂番号と優先度を **読みます**
2. 優先度がすでに新しい値なら、書きません（「すでに 1 だったため、変更していません」）。前の試行が反映済みだった場合もここで止まります
3. 改訂番号が投稿の時点から変わっていれば、**書きません**。承認を取り消して確認待ちに戻し、ADO の今の改訂番号と優先度で `#N` を出し直します。前の `OK N` は新しい投稿より上にあるので効きません。確かめて、もう一度 `OK N` と返信してください
4. 変わっていなければ、改訂番号を確かめる操作（JSON Patch の `test /rev`）と優先度の変更を、1 回だけ送ります。読んでから送るまでの間に誰かが更新した場合は、ADO が変更全体を拒否します（書けていない失敗として扱います）
5. 応答に、新しい改訂番号と新しい優先度がそろっていなければ、成功とはしません（「反映されたかどうか分かりません」）

結果は自分とのチャットへ返り、`executions.jsonl` に残ります（状態: `running` / `done` / `stale`（確認し直し）/ `failed` / `unknown` / `closed` / `skipped`）。

## 結果が分からないとき

タイムアウト・切断・502〜504・応答の不足は「分からない」です。**自動では送り直しません**。

- ADO で優先度を確かめて、新しい値になっていれば `済 N`
- なっていなければ `再実行 N`（または結果の投稿にある `再実行 N-k`）。kimeru は送る前にもう一度 ADO を読み、反映済みなら書かず、改訂が変わっていれば確認し直しに回します

## 作業の完了とは別

優先度を変えたことは、案件の作業が終わったことではありません。進捗は、これまでどおり `work set N done` で記録します。

## 確認の状況

人工の ADO 応答（テスト）でだけ確認しています: 既定で無効、承認の表示、改訂の一致・不一致、反映済み、応答の不足、タイムアウト後の `再実行`・`済`、記録の改ざん、書き先の変更、書けない変更。実際の ADO での確認は未実施（NOT_RUN）です。試すときは、テスト用の作業項目で、[実機確認の手順](managed-pc-check.md) の T10 の後に 1 件だけ行ってください。
