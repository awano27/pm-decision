# 承認した返信を相手のチャットへ送る（`送る N`）

既定では、承認した返信は相手へ送りません。承認の投稿の文面を、`送る N` と返したときだけ、相手の 1 対 1 のチャットへ PC の Teams から **1 回** 送ります。承認（`OK N`）だけでは送りません。

## 有効にする

```powershell
python -m kimeru config set execute teams.reply
```

- `ado.comment` と並べて書けます（`ado.comment,teams.reply`）。
- 元に戻す: `python -m kimeru config unset execute`。戻したあとは、`送る N` と返しても送りません。

## 動き

1. 承認の投稿（`[kimeru #N]`）は、これまでどおりです。投稿の時点で、返信の文面と送り先（相手の 1 対 1 のチャット）を固定して保存します。投稿のあとに下書きや設定を変えても、送るのは固定した文面です。
2. `OK N` で承認すると、送信用の投稿 `[kimeru 送信用 #N]` の末尾に 1 行が付きます: 「送る N で、この文面をそのまま 〈相手の名前〉 とのチャットへ送ります（PC の Teams から 1 回）」。この時点では送りません。
3. `送る N`（`送る #N` も可）と返すと、固定した文面を相手のチャットへ 1 回送り、結果を `[kimeru 実行 #N k]` で返します。
   - 「送りました（〈相手〉 とのチャット）」
   - 「送れませんでした（理由）。承認は残っています」（直したら `再実行 N` と返信）
   - 「送れたか分かりません」（`済 N` か `再実行 N` と返信）
4. 同じ `送る N` を読み直しても、2 回目は送りません。
5. 送るのは、元のイベントが **1 対 1 のチャット** で、相手のチャットの識別子が記録されている件だけです。グループ・メンション経由・識別子の無い件は送りません。承認の投稿に「送れません（グループ／相手が特定できない）」と出ます。その件の `送る N` は、後述の期間に読まれたときだけ「対象外」と記録します（送りません）。
6. `--send` を付けない実行（`approvals`・`daily`）で `送る N` を返したときは、送信は行わず、依頼だけを記録します。次の `--send` の実行で、1 回だけ送ります。
7. 実行の記録（`executions.jsonl`）には、状態と時刻と、送った文の先頭 120 字が入ります。相手のチャットの識別子は入りません。
8. 承認（`OK N`）から **48 時間** のあいだだけ、kimeru は `送る N` を探すために自分とのチャットを読みます。この間は、ほかの理由がなくても毎回の実行で自分とのチャットを読むので、Teams の画面が動くことがあります。48 時間を過ぎた `送る N` は読まず、何も返しません。その件は、送信用の投稿の文面を手で送ってください。
9. 設定を入れていないときは、`送る N` を読むための読み取りを増やしません。kimeru がほかの理由で自分とのチャットを読んだときに限り、`送る N` に「送りません（記録だけです）」と 1 回返し、`executions.jsonl` に `skipped`（`not_enabled`）の 1 行を残します。同じ行を読み直しても、返事と記録は増えません。
10. 設定を入れていないときに承認した件は、承認の時点で文面を固定していません。その件の `送る N` には、設定を入れたあとでも「送りません」と返します（`送る N` と返すたびに）。そのときは、送信用の投稿の文面を手で相手のチャットへ送ってください。

## 送り先の確認

- 送る前に、kimeru は相手のチャットを開き、そのヘッダーの識別子（`chat-header-…`）が記録と一致するかを確かめます。題名では判定しません。一致しなければ何も貼らず、「送れませんでした（相手のチャットを確かめられず、何も貼っていません）」と出ます。
- 相手の入力欄に下書きがあるときは貼りません（送れませんでした）。
- 貼った文が、承認した文と一字一句一致することを読み返してから送ります。相手のチャットの本文は読みません。
- 送ったあとは、チャットの一覧にある自分の行（「あなた: …」）の先頭で、送った文が見えたかを確かめます。見えなければ「送れたか分かりません」になります。
- 開いていたチャットへ戻します。戻せなかったときは、その旨を結果の投稿に書きます。

## 結果が分からないとき

1. 「送れたか分かりません」の投稿が 1 回だけ来ます。
2. Teams で、相手とのチャットに自分の送った文があるかを見ます。
3. **あった**: `済 N` と返信します。その件は閉じられ、もう送りません。
4. **無かった**: `再実行 N` と返信します。もう一度だけ送ります。kimeru は、送る前に相手のチャットを読んで確かめることはしません（相手の本文は読まない約束のため）。だから、Teams を見てから返信してください。
5. 「送れませんでした」（確かに送っていない）のときは、直してから `再実行 N-k`（結果の投稿に書いてあります）か `再実行 N` と返信します。`再実行` は 1 回の返信につき 1 回だけ効きます。

`送る N` と返していない件には、`再実行` は効きません。最初に送るのは `送る N` だけです。

## 止める

- `python -m kimeru config unset execute`（または `config set execute ado.comment`）で、`teams.reply` を外します。外したあとの `送る N` は送りません。
- 設定を外しているあいだ、kimeru は `送る N` のためだけには自分とのチャットを読みません。返事が来るのは、ほかの理由で読んだときだけです（動き 9）。
- 承認の記録は残ります。承認を取り消す操作はありません。

## 実機で確かめること

- 偽の読み手（テスト）と、PowerShell の構文検査だけで確かめています。実際の Teams で送るのは、この手順を試したあとにしてください。
- `tools/teams-self.ps1` の `sendto` の本物の分岐（送り先が違う・相手の入力欄に下書きがある・一覧に見えない）は、テストでは実行していません。偽の読み手は、それぞれの答え（`wrong chat`・`draft`・`unknown`）を返すだけで、貼ったかどうかの記録だけを確かめています。本物の分岐は、下の手順で実機で一度確かめてください。
- 最初の 1 通は、自分ともう 1 つのアカウントの 1 対 1 のチャットで試してください（手順は [管理された PC 動作確認](managed-pc-check.md) の「送る N の往復」）。
