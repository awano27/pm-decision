# 初めて使う人の観察（30 分）の手順と記録様式

kimeru を知らない人が、README だけで最初の成功に届くかを観察する手順です。結果は集計だけを [evaluation.md の「利用者の環境での結果」](evaluation.md#利用者の環境での結果) に載せます。本文・氏名・社名・画面の録画は残しません。

> まだ実施していません（2026-10 時点）。協力していただける方を探しています。

## 対象と人数

- Windows 10/11 と Teams デスクトップを業務で使う、ソフトウェア開発の PM。kimeru の説明を受けていない人
- 3〜5 名。作者との関係（同じ組織の別チーム／別の組織）は記録に書く

## 渡すもの・しないこと

- 渡すのは README の URL だけ。口頭の説明・画面共有での手助けはしない
- 質問はメモで受け、回数と内容（見出し名の範囲で）を記録する
- 画面共有は demo の間だけ。業務の画面は映さない

## 始める前（5 分）: 理解の 5 問

README を読む前に、分かる範囲で答えてもらう（分からないは「分からない」でよい）。

1. スマホに通知は来るか
2. 承認したあと、相手に送るのは誰か
3. 何も設定しないとき、判断はどのモデルがするか
4. 記録はどこに残り、どう消すか
5. Jev を選ぶと、何が PC の外へ出るか

## 観察（30 分まで）

| 時刻 | 記録すること |
|---|---|
| 開始 | README を開いた時刻 |
| 途中 | 打ったコマンド、止まった場所（README の見出し名か画面名）、質問の回数 |
| 終了 | `out\demo\report.html` を自分で開き、「判断 9 件」のまとめを読み上げた時刻。または 30 分経過・本人の中止（理由） |

成功の定義: README の「まず動かす」の手順で、README と同じまとめ 5 行と `report.html` が得られ、終わったあとに「demo はキーワードの簡易判定」「外へ何も送っていない」を自分の言葉で言える。

## 終わったあと（5 分）

- 同じ 5 問にもう一度答えてもらう
- 自由記述 3 問: 分からなかったこと／怖かったこと／止め方・消し方が分かったか
- `python -m kimeru config show --share` の 1 行目（版と commit、OS、Python）

## 集計の様式（公開するもの）

| 項目 | 書くこと |
|---|---|
| 人数 | 参加者数（作者との関係の内訳） |
| 初回成功 | 成功した人数、かかった分（中央値と範囲）、中止の人数と理由の区分 |
| 止まった場所 | README の見出し名ごとの件数 |
| 質問 | 回数の合計と中央値 |
| 理解 5 問 | 前と後の正答数（中央値と範囲） |
| 出たエラー | トレースバックの件数、何も出ずに終わった件数 |
| 公開の許可 | 許可のあった人数（許可の無い人の値は人数にだけ含める） |

3 名以下の結果は「観察」と書き、割合（%）だけでは書きません。
