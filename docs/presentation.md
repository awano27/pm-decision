## 前日までの準備（開発用 PC）

1. `C:\develop\kev-bundle\start-kev.cmd` で Kev を起動しておく（起動に数分、メモリ約 10GB）
2. リハーサル兼記録: `python -m kimeru --backend kev --out demo-out demo --step --record demo\demo-recording.json`
   （`--step` は各イベントの前で Enter 待ち。話す速さに合わせられる。記録ファイルは `demo\`、リポジトリには入らない）
3. 代替の確認: `python -m kimeru --out demo-out demo --step --replay demo\demo-recording.json`
   （モデルなしで同じ表示とレポートを再生。Kev が落ちたら当日はこれを使う）。念のため画面の録画も 1 本
4. ターミナルの文字を大きく（画面共有で読める 20pt 以上）、ウィンドウ幅は 120 桁程度
5. 通知を切る（Teams・メール）。画面共有は「ウィンドウ」単位で、ターミナルとブラウザだけ

## 想定問答

**精度はどのくらい？**
架空の 99 件で、Kev は誤った行動 0、重大な取りこぼし 0。その代わり約 4 割を人に回します。自動化の割合をどこまで上げられるかが課題で、実データでの調整がこれからです。

**Jev の方が精度は高いのでは？数値は？**
Jev の性能数値は利用規約で公開できません。社外に出してよいデータなら Jev、会社のデータは Kev、という使い分けです。

**会社のデータが社外に出ない？**
Kev は PC の中（127.0.0.1）だけで動き、起動時もオフライン設定です。Teams の読み取りも画面操作なので、クラウドに送るものはありません。

**Teams を画面操作で読むのは壊れない？**
壊れえます。Teams の画面構造が変わると読めなくなるので、診断（`teams-self.ps1 -Action diag`）と、自分とのチャットの位置を覚え直す仕組み（`-Action learn`）を入れています。本来は Graph API ですが、テナント管理者の同意が必要なため、まずは同意なしで始められる方法を選びました。

**管理者権限や IT 部門の承認は？**
管理者権限は不要です（Python・Kev は利用者のフォルダ、自動運転は利用者のタスクスケジューラ）。ただし社内ルール（持ち込み・画面の自動操作・AI 利用）の確認は必要で、そこは相談させてください。

**誤って変な書き込みをしない？**
今は外部への書き込みはすべて試し実行（記録のみ）です。本番化は操作の種類ごとに段階的に行い、最初は ADO へのコメントのような影響の小さいものから考えています。人の確認を経た処理しか実行しない設定も可能です。

**生成 AI（ChatGPT など）で良いのでは？**
文章を作らせると検証が難しく、結果も毎回ぶれます。kimeru は「選択肢と確率」だけを受け取り、行動はテンプレートで決めるので、テストと評価ができ、安全網も組み込めます。

**判断の型や質問は自分で増やせる？**
判断グラフ（`graphs/*.json`）と進め方の型（`playbooks/*.json`）は JSON なので追加できます。読み込み時に、行き先の漏れやループがないか検証します。追加したら `eval/` の評価で確かめます。

**CPU で遅くない？**
1 件の判断は開発用 PC で中央値 3.6 秒。5 分ごとの自動運転なので実用上は問題ありません。会社 PC の速度は確認中です。

**Copilot（Microsoft 365）とどう違う？**
Copilot は要約や下書きが得意で、kimeru は「決めて、次の行動につなぐ」部分を担います。会議のまとめは Copilot のものを取り込む予定です。
