# 最初の 30 分: 1 回動かすまで

デモを見てから、自分の Teams で 1 回動かすまでの順番です。上から 5 段。各段に「所要時間」「コマンド」「できたと分かる印」「失敗したとき」を書きました。新しい機能はありません。

この手順では、相手への返信や起票は行いません。自分とのチャットへ送るのは、3 段目の試験の 1 通だけです（`[y/N]` で `y` と答えたときだけ）。

## 1. 5 分: デモを見る

- **所要時間**: 5 分（`--pace 0` で待ちを省く）
- **準備**: [まず動かす](../README.md#-まず動かす) のとおり clone するか ZIP を展開し、PowerShell で `python --version` が 3.10 以上であることを確かめる。1 件の流れ（届く → 整理 → 修正 → 承認 → 記録）だけなら、先に `python -m kimeru try` を実行すると 1 秒ほどで見られます（この PC の設定を読まず、外へ何も送りません）。
- **注意**: `demo` は `try` と違い、この PC の writer の設定を使います。writer を設定した PC では、返信案の材料がその writer の提供元へ送られます。
- **コマンド**:

```powershell
python -m kimeru --backend stub --out out/demo demo --pace 0
```

- **できたと分かる印**: 最後に `=== まとめ` が出て、`out/demo/report.html` をブラウザで開ける。
- **失敗したとき**: [困ったとき](usage.md#困ったとき)。デモは `out\demo` にだけ書き、Teams や ADO には書き込みません。

## 2. 5 分: 自分の Teams を読めるか見る

- **所要時間**: 5 分（数分かかる。読み取りだけで、何も入力・送信しない）
- **準備**: Teams の画面の自動操作（UI Automation による読み取り）が、組織で認められているかを先に確かめる。Teams を開き、チャット一覧を表示しておく。kimeru は Teams を自動では起動・表示しません。
- **コマンド**: `run-auto-check.cmd` をダブルクリック
- **できたと分かる印**: `kimeru-auto-check-result.txt`（クリップボードにも入る）で、T1 と T3 が OK。
- **失敗したとき**: 「Teams が起動していません」や「Teams のウィンドウが表示されていません（起動はしています）」と出たら、Teams のウィンドウを開いてから、もう一度実行する（[困ったとき](usage.md#困ったとき)、[自動の確認](managed-pc-check.md#自動の確認ダブルクリック-1-回何も送らない質問しない)）。

## 3. 5 分: 自分とのチャットへ試験の 1 通

- **所要時間**: 5 分
- **準備**: Teams で自分とのチャットが見える状態にする。宛先は自分だけ。
- **コマンド**:

```powershell
.\run-check.cmd T5
```

- **確認**: 実行の前に `[y/N]` と聞かれる。`y` のときだけ送る。Enter だけなら送らず SKIP になる。
- **できたと分かる印**: 自分とのチャットに `[kimeru 試験 #N]` で始まる 1 通が届く（N は乱数）。
- **失敗したとき**: [実機確認の T5](managed-pc-check.md#t5-送信と-iphone-からの返信外部送信あり-宛先は自分のみ)。

## 4. 10 分: 1 サイクルを動かす（送らない）

- **所要時間**: 10 分
- **準備**: 2 段目と同じく、Teams を開いてチャット一覧を表示しておく。
- **コマンド**:

```powershell
python -m kimeru --backend stub daily --once
```

- **送らない**: `--send` を付けないので、自分とのチャットへの投稿は送られません。Teams の入力欄に貼られても、Enter で送らないでください。
- **できたと分かる印**: 1 行の JSON が出る。`pull_teams` に取り込み件数、`judge` に判断件数が入る。人の確認待ちになった件は `out/queue.jsonl` に 1 行ずつ増える。
- **通知を止める**: PC の Windows 通知が煩わしければ、`KIMERU_TOAST=0` を設定する。止まるのは PC の通知だけです。
- **失敗したとき**: JSON の項目に `error:` で始まるものがあれば、[困ったとき](usage.md#困ったとき)。

## 5. 5 分: 本物の判断モデルへ

- **所要時間**: 5 分（Kev か Jev の準備ができているとき）
- **コマンド**: Kev を起動してから（[Kev の持ち込み用フォルダ](kev-bundle.md)）、次を実行する。

```powershell
python -m kimeru --backend kev daily --once
```

Jev を使うなら、`TYPESAFE_API_KEY` を環境変数で設定してから `--backend jev` を指定します。鍵の値は手順書やファイルに書かないでください。

- **できたと分かる印**: 4 段目と同じ 1 行の JSON で、`error:` で始まる項目がない。
- **どちらも無い間**: `stub` で動きますが、これはキーワードによる簡易判定です。語の一致だけで判断しています。
- **失敗したとき**: [困ったとき](usage.md#困ったとき)（「判断モデルに接続できません」「TYPESAFE_API_KEY is not set」の行）。
